# 트레이닝 모드(TR.WAR) 한글 주입

컴플리트 박스 네 번째 항목인 **트레이닝 모드**용 도구. v0.10.5 에서 두 가지를 한다.

1. **전투가 멈추던 문제 수정** — 전투 대사 아카이브 `BMESS2/3/4.BIN` 의 목차표는
   게임이 파일에서 읽지 않고 **실행파일 안 사본**을 쓴다. 한글화하며 세 아카이브를
   재패킹했는데 `SECOND.WAR`/`THIRD.WAR`/`EX.WAR` 만 갱신하고 `TR.WAR` 을 빠뜨렸다.
   낡은 표를 쓰면 첫 전투 대사가 블록 한가운데를 가리켜 **대사가 안 나오고 전투가
   그대로 멈춘다.** `TR.WAR` 의 세 표(`0x103678`/`0x103CB8`/`0x1042F8`)를 교체한다.
2. **UI 한글화** — `TR.WAR` 은 EX 와 같은 엔진이라 UI 테이블 본문이 **헤더 4바이트만
   빼면 EX 와 바이트까지 동일**하다(레코드 3,282개 전수 대조 확인). 그래서 EX 에서
   이미 폭 검증을 통과한 번역을 그대로 재사용한다.

## 파일

- `make_tr_injector.py` — `inject_ex_ui.py` → `inject_tr_ui.py` **기계 변환**.
  500줄을 손으로 다시 쓰면 검증된 로직(스팬 폭 보존·앵커 가드·중간 패딩)을 잃기
  쉬워서, 필요한 치환만 적용하고 각 치환이 정확히 1회 일어났는지 확인한다.
  **주입기를 고칠 일이 생기면 EX 쪽 원본을 고치고 이걸 다시 돌린다.**
- `inject_tr_ui.py` — 위 변환 결과 (생성물).
- `tr_extra_records.py` — TR 전용 보조. 유닛 타입 표, `無有`, 외래 맵/시스템 레코드,
  포인터 있는 잔여 레코드 재배치, BMESS 목차표 교체.
- `verify_tr_offsets.py` — **주입 전 게이트.** TR 오프셋이 정말 EX 의 대응 위치인지
  레코드 단위로 대조한다. 상수 델타로 밀어 넣지 않는다.
- `verify_tr_glyphs.py` — **주입 후 게이트.** 도너로 내준 폰트 슬롯을 살아 있는
  레코드가 가리키지 않는지 거꾸로 확인한다(과거 프리즈의 원인이던 유형).
- `build_tr_full.py` — BMESS 표를 얹고 게이트 5종을 돌려 최종 `TR.WAR` 을 만든다.
- `tr_survey.py` — 정찰(패치본에서 TR.WAR 추출, 표 상태 확인, 일본어 레코드 스캔).
- `tr_align_overrides.json` — 폭이 모자란 스팬의 대체 표현.

## 함정 두 가지 (둘 다 실제로 밟았다)

- **레코드 끝을 단순 0xFF 스캔으로 찾으면 안 된다.** 컨트롤 코드의 *인자 바이트*가
  0xFF 일 수 있다. 토큰 문법으로 걸어야 한다. (맵 상태창 레코드가 51B 인데 32B 로
  잘려 읽혀 한글 50B 가 "넘침"으로 버려졌다.)
- **필드상대 포인터는 4바이트 정렬이 아니다.** 실측하니 136개 중 131개가 오프셋
  `%4 == 1` 이다. 정렬 스캔으로 색인을 만들면 잔여 레코드 116건을 통째로 놓친다.
- 부수적으로, `ui_master` 레코드에서는 `0xF0~0xF5` 가 **UI-VM 옵코드**라 글리프
  선두바이트가 아니다. 대사 문법으로 읽으면 존재하지 않는 글리프를 쓰는 것처럼
  보여 허위 경보가 뜬다.

## TR 이 EX 와 다른 곳

- 시스템 설정창(`ui_master[39]`)에 '퀵 컨티뉴' 안내 두 줄이 없다(30바이트 짧음).
- 시스템 메뉴 마지막 항목이 `セ-ブ`(저장)가 아니라 `終了`(종료)다.
